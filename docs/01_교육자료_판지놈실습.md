# 판지놈(Pangenome) 실습 교육자료 — 초보자용

> KOGO 제20회 통계유전학 워크샵 Day 2 실습을 처음 접하는 사람도 이해할 수 있도록
> 정리한 자료입니다. **왜** 하는지, **어떻게** 하는지, **결과를 어떻게 읽는지**를
> 실제 서버 실행 결과(강사 정답과 일치)와 함께 설명합니다.

---

## 0. 큰 그림 — 판지놈이란 무엇이고, 왜 쓰는가

**기존 방식(선형 참조 유전체):** 사람 유전체 분석은 지금까지 GRCh38 같은
**한 사람 기준 서열 하나**에 내 read를 맞춰(mapping) 왔습니다. 문제는, 이 기준
서열에 없는 서열(특정 집단에만 있는 삽입, 다른 형태의 구조 변이 등)을 가진 read는
**맞출 곳이 없어 버려지거나 틀리게 맞춰진다**는 점입니다 (reference bias, 참조 편향).

**판지놈:** 한 사람 대신 **여러 사람의 유전체를 하나의 그래프**로 합친 것입니다.
- **노드(node)** = 서열 조각, **엣지(edge)** = 조각들이 이어지는 경로.
- 사람마다 다른 부분에서 그래프가 **거품(bubble)처럼 갈라졌다 합쳐집니다.**
- 각 사람의 유전체는 이 그래프를 지나가는 하나의 **경로(path/walk)**.

이번 실습의 판지놈은 **한국인 판지놈(KPP) 초안**의 일부(chr2:1–5Mb, "toy" 크기)라서
노트북·실습 시간 안에 돌아갑니다. 전체 판지놈은 수백 GB라 실습엔 부적합합니다.

**전체 흐름 한눈에 보기:**

![KOGO Day2 전체 데이터 흐름](../figures/kogo_pipeline_overview.png)

**이번 실습 그래프 규모(실제 값):** 노드 73,299개 · 엣지 99,694개 · 경로/walk 16개.
16개 경로 = 참조 2개(GRCh38, CHM13) + 판지놈 구축에 쓴 4명 × 각 2벌(부계·모계) = 8,
그 외 나머지.

## 1. 실습 데이터 — 무엇이 주어지는가

| 파일 | 정체 | 어디에 쓰나 |
|---|---|---|
| `OUR.gbz`, `OUR.full.gbz` | 판지놈 그래프(압축 형식) | 매핑·변이호출의 기준 |
| `OUR.hapl` | 하플로타입 패널 | 새 샘플 맞춤 그래프 생성 |
| `OUR.gfa.gz` | 그래프의 텍스트 형식(GFA) | growth curve 계산 입력 |
| `OUR.vcf.gz` | 판지놈이 담고 있는 4명의 변이 목록 | **실습1** 분석 대상 |
| `HG00438_*.fq.gz`, `HG02257_*.fq.gz` | 판지놈에 **없는** 새 2명의 short-read | **실습2·3** 분석 대상 |
| `GRCh38.chr2_1-5Mb.fa` | 선형 참조 서열 | 실습3 DeepVariant 좌표 기준 |

**꼭 구분해야 할 개념 (가장 중요):**

- **실습 1** = 판지놈 그래프가 **이미 담고 있는** 4명(sample01~04)의 변이를 분석.
  → 새 데이터 필요 없음. "이 판지놈 안에 어떤 변이들이 들어 있나?"
- **실습 2·3** = 판지놈에 **없는 새 사람**(HG00438, HG02257)의 read를 가져와 분석.
  - 실습 2: 판지놈이 아는 **큰 변이(SV)** 를 이 사람이 갖고 있는지 확인 (genotyping)
  - 실습 3: 이 사람의 **작은 변이(SNV·INDEL)** 를 새로 찾아냄 (calling)

## 2. 실습 1 — 판지놈 구축 VCF 분석

### 1-② Growth curve (판지놈 성장 곡선)

**왜 하나?** "샘플을 한 명씩 더할 때마다 판지놈이 커버하는 서열이 얼마나 늘어나는가?"를
봅니다. 새 사람을 추가할 때 계속 새로운 서열이 나오면(곡선이 계속 오름) 판지놈이 아직
"포화"되지 않았다는 뜻 — 즉 더 많은 사람을 넣을수록 다양성이 계속 발견됩니다.

**어떻게?** `panacus ordered-histgrowth` 로 GFA 그래프에서 샘플을 순서대로 누적하며
커버되는 bp(염기쌍) 양을 계산합니다. 참조(GRCh38/CHM13)는 제외하고 순수 샘플만.

**결과 해석 (실제 값, coverage≥1·quorum=0 열):**

| 누적 샘플 | 커버 bp | 새로 추가된 양 |
|---|---|---|
| sample01 | 63,470 | (시작) |
| +sample02 | 79,252 | +15,782 |
| +sample03 | 92,278 | +13,026 |
| +sample04 | 98,382 | +6,104 |

![Growth curve 해석](../figures/growth_curve_explained.png)

→ 사람을 더할수록 커버 bp가 늘지만 **증가폭이 점점 줄어듭니다**(15,782 → 6,104).
이는 공통 서열은 앞 사람들이 이미 채웠고, 뒤로 갈수록 그 사람만의 고유 서열만
추가되기 때문입니다. 여러 quorum(몇 %의 샘플이 공유해야 세는지) 기준으로 함께 그리면,
"코어(core, 모두 공유)"와 "액세서리(accessory, 일부만)" 서열의 비율을 볼 수 있습니다.

### 1-③ 변이 타입 분류

**왜 하나?** 판지놈이 담은 변이(`OUR.vcf.gz`, 총 19,877개)가 **어떤 종류**인지
나눕니다. 변이는 크게 SNV(한 글자 치환) / non-SNV(삽입·결실·복합) / 그중 큰 것(SV)으로
구분됩니다.

**어떻게?** `bcftools` 로 타입별 분리:
- **SNV** = 한 염기 치환 (예: A→G)
- **non-SNV** = INDEL(삽입/결실) + MNP(여러 염기 치환) + 기타
- **SV(구조 변이)** = non-SNV 중 길이 차이가 **50bp 이상**인 큰 변이

**결과 해석 (강사 정답 = 서버 결과, 완전 일치):**

| 타입 | 개수 | 의미 |
|---|---|---|
| SNV | 16,149 | 대부분의 변이는 한 글자 치환 |
| non-SNV | 3,728 | 삽입/결실 등 (INDEL 3,263·MNP 453·기타 등) |
| 그중 SV(≥50bp) | 415 | 큰 구조 변이 (INDEL 388·MNP 34·기타 87) |

→ **변이의 대다수(약 81%)는 SNV**이고, 큰 구조 변이(SV)는 415개로 소수지만
질병·표현형에 큰 영향을 줄 수 있어 따로 봅니다. 판지놈의 강점이 바로 이 **SV를
그래프의 거품(bubble)으로 자연스럽게 표현**한다는 점입니다.

### 1-③ 집단 특이 / 개인 특이 변이

**왜 하나?** 우리 집단(sample01~04, "our")에만 있고 대조군(CHM13)에는 **없는** 변이를
찾습니다. "이 집단에 특징적인 변이는 무엇인가?"

**어떻게?** `bcftools isec`(교집합/차집합)로 our에는 있고 control에는 없는 loci 추출.

**결과 해석 (강사 정답 = 서버 결과):**

| 집단 특이 | 개수 |
|---|---|
| SNV | 10,430 |
| non-SNV | 2,047 |
| SV | 202 |

→ 전체 SNV 16,149개 중 **10,430개(약 65%)가 our 집단 특이** — CHM13에 없는, 이
집단을 특징짓는 변이입니다. 이어서 **개인 특이**(한 사람에게만 있고 나머지 3명엔 없는
변이)도 계산합니다(실제 값: SNV 기준 sample01=1,558 / 02=923 / 03=1,162 / 04=834).
개인차가 있는 건 정상이며, 각 개인의 고유성을 보여줍니다.

## 3. 실습 2 — vg giraffe SV genotyping (새 샘플)

**왜 하나?** 판지놈에 **없는 새 사람**(HG00438, HG02257)의 short-read를 판지놈에
맞춰서, **"판지놈이 아는 큰 변이(SV)를 이 사람도 갖고 있는가?"**를 판정(genotyping)합니다.

### 2-① 개인 맞춤 그래프 만들기 (KMC + vg haplotypes)

**왜?** 전체 판지놈(모든 사람의 모든 변이)에 그냥 맞추면 느리고 노이즈가 많습니다.
그래서 **이 샘플의 read에 실제로 나타나는 부분만 남긴 개인 맞춤 그래프**를 먼저 만듭니다.

**어떻게?**
- `KMC` : read를 **k-mer**(29글자 조각)로 쪼개 세어, 이 사람이 실제로 가진 서열 파악
- `vg haplotypes` : 그 정보로 하플로타입 패널에서 이 사람에 맞는 경로만 뽑아
  `_sampled.gbz`(맞춤 그래프) 생성

### 2-② 매핑 (vg giraffe)

**왜?** read가 그래프의 어느 경로에 앉는지 찾습니다(선형 참조의 BWA/bowtie에 해당).

**어떻게?** `vg giraffe` 로 read를 맞춤 그래프에 정렬 → **GAM**(그래프 정렬 파일).

**결과 해석 (강사 정답 = 서버 결과):**
- HG00438: 전체 read 1,230,694개 중 **aligned 805,888개** 정렬 성공.
→ 판지놈에 없던 새 사람인데도 상당수 read가 그래프에 잘 붙습니다. 선형 참조 대비
판지놈의 장점(참조 편향 감소)이 여기서 나타납니다.

### 2-③ SV genotype 호출 (vg pack + vg call)

**왜?** 정렬된 read가 그래프의 각 거품(bubble=변이 자리)을 **얼마나 지지하는지** 세어,
이 사람의 각 SV 유전형(0/0, 0/1, 1/1)을 정합니다.

**어떻게?** `vg pack`(위치별 read 지지량 계산) → `vg call`(유전형 판정) → 두 샘플 병합.

**결과:** `Total_merged.chr2_1-5Mb.vcf.gz` — 두 샘플 통합 SV genotype VCF (변이 5,040개).
→ 이제 "HG00438과 HG02257이 판지놈의 어떤 SV를 각각 갖는지" 표로 정리된 것입니다.

## 4. 실습 3 — Pangenome-aware DeepVariant (새 샘플의 작은 변이)

**왜 하나?** 실습2가 **큰 변이(SV)**를 다뤘다면, 실습3은 같은 새 샘플의
**작은 변이(SNV·INDEL)**를 **정밀하게 호출**합니다. DeepVariant는 딥러닝 기반
변이 호출기로 정확도가 높고, 여기서는 **판지놈 정보를 추가 채널로 활용**해
참조 편향을 줄인 버전(pangenome-aware)을 씁니다.

### 3-① surject — 그래프 정렬을 선형 좌표로 변환

**왜?** DeepVariant는 **선형 참조(GRCh38) 좌표의 BAM**을 입력으로 받습니다. 그래서
실습2에서 만든 그래프 정렬(GAM)을 GRCh38 좌표로 **투영(surject)**해 BAM으로 바꿉니다.

**어떻게?** `vg surject` 로 GAM → BAM, contig 이름을 `chr2`로 정리, index/flagstat.

**결과 해석 (강사 정답 = 서버 결과):**
- HG00438: **mapped 804,384개 (65.36%)**.
→ 그래프에 정렬됐던 read가 선형 좌표로도 잘 옮겨졌습니다. 이 BAM이 DeepVariant 입력.

### 3-② DeepVariant + GLnexus

**왜?** 각 샘플의 SNV·INDEL을 호출하고(DeepVariant), 여러 샘플을 하나의 다중샘플
VCF로 **공동 genotyping**(GLnexus)합니다.

**어떻게?** `run_pangenome_aware_deepvariant`(판지놈 채널 사용) → 샘플별 VCF/gVCF →
`glnexus_cli`로 통합.

**결과 해석 (실제 서버 값):**
- 샘플별 원시 변이: HG00438 = 21,838개, HG02257 = 21,733개 (필터 전, gVCF 기반)
- **GLnexus 통합 후: 6,703개** (품질·정렬 기준으로 정제·통일된 최종 다중샘플 변이)
- 최종 파일: `OUR.pgdv.GLnexus.chr2_1-5Mb.vcf.gz` (샘플 2명 통합)

→ 원시 변이 수(약 2.1만)보다 통합본(6,703)이 적은 것은 정상입니다. GLnexus가 저품질
변이를 걸러내고 두 샘플에서 같은 자리는 하나로 통일하기 때문입니다.

## 5. 전체 요약 — 한 장 정리

```
[입력]  판지놈 그래프 + 구축 VCF + 새 샘플 read + GRCh38
   │
   ├─ 실습1 (구축 VCF 분석) ── 판지놈이 담은 4명의 변이
   │     ① growth curve   : 샘플 늘수록 커버 bp 증가(포화 확인)
   │     ② 변이 분류       : SNV 16,149 / non-SNV 3,728 / SV 415
   │     ③ 집단·개인 특이  : 집단특이 SNV 10,430 ...
   │
   ├─ 실습2 (새 샘플 SV genotyping)
   │     KMC → 맞춤그래프 → giraffe 매핑 → pack/call
   │     → Total_merged.vcf.gz (SV 유전형, 변이 5,040)
   │
   └─ 실습3 (새 샘플 small variant)
         surject → GRCh38 BAM → DeepVariant → GLnexus
         → OUR.pgdv.GLnexus.vcf.gz (SNV·INDEL, 통합 6,703)
```

**핵심 메시지 3가지:**
1. 판지놈은 여러 사람을 그래프로 합쳐 **참조 편향을 줄이고 SV를 자연스럽게** 다룬다.
2. 실습1은 판지놈이 **이미 아는** 변이 분석, 실습2·3은 **새 사람**을 판지놈으로 분석.
3. 큰 변이(SV)는 vg pack/call로 **genotyping**, 작은 변이(SNV/INDEL)는 DeepVariant로
   **calling** — 도구와 목적이 다르다.

## 6. 용어 사전 (빠른 참조)

- **판지놈(pangenome)** : 여러 유전체를 합친 그래프 형태의 참조
- **노드/엣지/경로(node/edge/path·walk)** : 그래프의 서열조각 / 연결 / 한 사람의 지나간 길
- **거품(bubble)·스나를(snarl)** : 그래프에서 변이가 생겨 갈라졌다 합쳐지는 구간
- **GBZ / GFA** : 판지놈 그래프의 압축 형식 / 텍스트 형식
- **하플로타입(haplotype)** : 한 벌(부계 또는 모계)의 서열
- **GAM** : vg의 그래프 정렬 결과 파일 (선형 BAM에 해당)
- **surject** : 그래프 정렬(GAM)을 선형 참조(GRCh38) 좌표 BAM으로 투영
- **SNV / INDEL / MNP / SV** : 단일염기치환 / 삽입·결실 / 다염기치환 / 구조변이(≥50bp)
- **genotyping vs calling** : 아는 변이의 유전형 판정 vs 변이 자체를 새로 찾기
- **quorum(정족수)** : growth curve에서 "몇 %의 샘플이 공유해야 세는지" 기준
