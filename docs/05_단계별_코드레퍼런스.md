# PHASE 1 — 실습 1 (판지놈 구축 VCF 분석)

## 1-① Growth curve

**작업 폴더:** `$WORK/02_pangenome_growth_curve`

### (1) GFA 압축 해제
```bash
pigz -dc -p 3 $ROOT/01_data_prepare/00_toy_pangenome/OUR.gfa.gz > OUR.gfa
# pigz 없으면: gzip -dc ... > OUR.gfa
```
| | |
|---|---|
| **IN** | `$DATA/OUR.gfa.gz` (3.3MB) |
| **OUT** | `$WORK/02_pangenome_growth_curve/OUR.gfa` (12.8MB) |

- `-dc` : decompress + stdout으로 (원본 유지)
- `-p 3` : 3스레드 병렬 해제 (pigz의 장점)

### (2) 참조/샘플 경로 목록 만들기
```bash
awk -F'\t' '$1=="W"{print $2}' OUR.gfa | grep -Ei  'grch38|chm13' | sort -u > ref.txt
awk -F'\t' '$1=="W"{print $2}' OUR.gfa | grep -Evi 'grch38|chm13' | sort -u > subset.txt
```
| | |
|---|---|
| **IN** | `OUR.gfa` |
| **OUT** | `ref.txt`(2줄: CHM13, GRCh38) / `subset.txt`(4줄: sample01~04) |

- `-F'\t'` : GFA는 탭 구분
- `$1=="W"` : **W(Walk) 라인만** 선택 = 하플로타입 경로 라인
- `print $2` : W 라인의 2번째 컬럼 = **샘플명**
- `grep -Ei` : 대소문자 무시(`-i`) 확장정규식(`-E`)으로 참조만 골라냄 / `-v`는 반대(제외)
- `sort -u` : 중복 제거 (한 샘플이 hap1·hap2 두 줄이므로)

### (3) panacus 성장 곡선 계산 ★핵심
```bash
RUST_LOG=info panacus ordered-histgrowth \
    -c bp -l 1,2,1,1,1 -q 0,0,1,0.5,0.1 \
    -S -e ref.txt -O subset.txt OUR.gfa > histgrowth.OUR.chr2_1-5Mb.tsv
```
| | |
|---|---|
| **IN** | `OUR.gfa`, `ref.txt`, `subset.txt` |
| **OUT** | `histgrowth.OUR.chr2_1-5Mb.tsv` (4행 = sample01~04) |

**옵션 의미 (가장 중요한 부분):**
| 옵션 | 의미 |
|---|---|
| `ordered-histgrowth` | **순서가 정해진** 성장 곡선 (샘플을 지정 순서대로 누적) |
| `-c bp` | count type = **염기쌍(bp)** 단위로 셈 (`node`/`edge`도 가능) |
| `-l 1,2,1,1,1` | **coverage 임계값** 5개 — 각 열마다 "노드가 최소 몇 개 하플로타입에 있어야 세나" |
| `-q 0,0,1,0.5,0.1` | **quorum(정족수)** 5개 — "샘플의 몇 %가 공유해야 세나" (0=합집합, 1=전부공유=코어) |
| `-S` | 통계 요약 출력 |
| `-e ref.txt` | **제외(exclude)** — 참조(GRCh38/CHM13) 경로는 곡선에서 뺌 |
| `-O subset.txt` | **순서(order) 지정** — 이 파일 순서대로 샘플을 누적 |
| `RUST_LOG=info` | Rust 로그 레벨 (진행상황 보기) |

`-l`과 `-q`는 **쌍으로 5개 열**을 만듭니다: (cov≥1,q=0)=전체 합집합 / (cov≥2,q=0) /
(cov≥1,q=1)=**코어** / (q=0.5)=절반 공유 / (q=0.1).

> ⚠️ **버전 주의:** bioconda 최신 panacus(0.5.1/0.5.2)는 이 명령에서 `Collected 0 paths`로
> **빈 TSV**가 나오는 버그가 있습니다. **`panacus=0.4.1`로 고정**해야 정상입니다.
> (서버에서 실제로 겪었고, 0.4.1 재설치 후 해결됨)

### (4) 그림 그리기
```bash
python $WORK/bin/01_pangenome_growth_curve.py histgrowth.OUR.chr2_1-5Mb.tsv \
    -o OUR_chr2_1-5Mb_growth_curve -f png
```
| | |
|---|---|
| **IN** | `histgrowth.OUR.chr2_1-5Mb.tsv` |

- `-o` : 출력 파일명 (확장자 제외)
- `-f png` : 포맷 (기본 pdf, `pdf/png/svg/eps` 선택)
- `-l` : 범례 위치, `-s` : figsize (기본 `12 8`) — 강사 원본 `.py` 옵션

## 1-② 변이 타입 분류

**작업 폴더:** `$WORK/03_variant_analysis` → 출력 서브폴더 `01_type_split/`
**공통 입력:** `$DATA/OUR.vcf.gz` (총 19,877개 변이, 샘플 5명: CHM13+sample01~04)

### (1) SNV만 추출
```bash
bcftools view -v snps --threads 3 $DATA/OUR.vcf.gz \
  | bcftools view -V indels,mnps,other --threads 3 -o 01_type_split/SNVs_only.vcf.gz -Oz
```
| **OUT** | `01_type_split/SNVs_only.vcf.gz` → **16,149개** |
|---|---|

- `-v snps` : **포함(include)** 할 타입 = SNP
- `-V indels,mnps,other` : **제외(exclude)** 할 타입 — 대문자 V가 제외!
- **두 번 거는 이유:** 다대립(multiallelic) 사이트는 SNP와 INDEL을 동시에 가질 수 있어,
  `-v snps`만 쓰면 그런 사이트가 섞여 들어옵니다. 제외 필터를 한 번 더 걸어 **순수 SNV만** 남김.
- `-Oz` : 출력 형식 = 압축 VCF(bgzip). `-o` : 출력 파일명
- `--threads 3` : 압축/해제 병렬화

### (2) non-SNV 추출
```bash
bcftools view -v indels,mnps,other --threads 3 $DATA/OUR.vcf.gz \
    -o 01_type_split/non_SNVs.vcf.gz -Oz
```
| **OUT** | `01_type_split/non_SNVs.vcf.gz` → **3,728개** (SNP234·INDEL3263·MNP453·기타226) |
|---|---|

### (3) SV(≥50bp) 추출 ★3단계 파이프라인
```bash
# ① 다대립 분해(split) — 정규화는 하지 않음
bcftools norm --threads 3 -m -any -N 01_type_split/non_SNVs.vcf.gz \
  | bcftools view -V snps --threads 3 -Oz -o 01_type_split/tmp.vcf.gz
# ② 양끝 trim 후 길이차 ≥50bp만 남김 (강사 제공 파이썬)
python $WORK/bin/01_filter_SV_by_trim.py 01_type_split/tmp.vcf.gz 01_type_split/tmp_SV.vcf.gz
# ③ 다시 합침(join)
bcftools norm --threads 3 -m +any -N -Oz -o 01_type_split/SVs.vcf.gz 01_type_split/tmp_SV.vcf.gz
```
| | |
|---|---|
| **IN** | `01_type_split/non_SNVs.vcf.gz` |
| **OUT** | `01_type_split/SVs.vcf.gz` → **415개** (INDEL388·MNP34·기타87) |

**옵션 의미:**
| 옵션 | 의미 |
|---|---|
| `norm -m -any` | 다대립 사이트를 **한 줄씩 분해**(split). `-`가 split, `+`가 join |
| `norm -m +any` | 분해된 걸 **다시 한 줄로 합침**(join) |
| `-N` | **정규화 안 함(no normalization)** — 참조 FASTA 없이 실행, allele 그대로 유지 |
| `view -V snps` | split 후 남은 SNP 제외 |

**왜 split→filter→join 인가:** 다대립 사이트에서 **allele 하나하나의 길이**를 봐야
SV 판정이 되므로 먼저 분해합니다. 판정 후 다시 합쳐 **site 단위로 카운트**합니다.
(합치지 않으면 826개 = allele 단위가 나옴. 415가 site 단위 정답)

**`01_filter_SV_by_trim.py` 내부 로직 (cyvcf2 사용, 인자 2개):**
- `trim_both(ref,alt)` : 공통 **prefix·suffix를 잘라냄** → 실제 변이 부분만 남김
- 판정: MNP(`len_ref==len_alt≥50`) / INDEL(`is_indel & |길이차|≥50`) /
  치환(`not indel & (len_ref≥50 or len_alt≥50)`)
- 한 site에서 조건 만족 allele을 찾으면 **한 번만 기록하고 break**

bcftools +counts 01_type_split/SNVs_only.vcf.gz >> 01_type_split/loci_count.txt

| **OUT** | `01_type_split/loci_count.txt` (검증용 정답 대조 파일) |

## 1-③ 집단 특이 변이

**출력 폴더:** `$WORK/03_variant_analysis/02_our_population_spec_var/`

### (1) 집단 명단 만들기
```bash
bcftools view -h $DATA/OUR.vcf.gz | grep -v "##" | tr '\t' '\n' | tail -n+10 \
    | grep -v "sample" | grep -P "HG|NA|CHM13" > 02_our_population_spec_var/control.txt
bcftools view -h $DATA/OUR.vcf.gz | grep -v "##" | tr '\t' '\n' | tail -n+10 \
    | grep "sample" | grep -vP "HG|NA|CHM13" > 02_our_population_spec_var/our.txt
```
| **OUT** | `control.txt` = `CHM13` / `our.txt` = `sample01~04` |
|---|---|

- `view -h` : **헤더만** 출력 / `grep -v "##"` : `##`메타 제외 → `#CHROM` 줄만 남김
- `tr '\t' '\n'` : 탭을 줄바꿈으로 → 컬럼이 한 줄씩
- `tail -n+10` : 10번째 줄부터 = VCF 고정 9컬럼(CHROM~FORMAT) 이후 = **샘플명들**
- ⚠️ `grep -P`(Perl 정규식)는 **GNU grep 전용** — macOS BSD grep에선 `-E`로 바꿔야 함

### (2) our에는 있고 control에는 없는 loci 추출 ★
```bash
for V in 01_type_split/*vcf.gz; do
  # our 집단에서 변이 있는 사이트
  bcftools view --threads 3 -S our.txt $V     | bcftools view --threads 3 -c1 -Oz > group_var.vcf.gz
  # control에서 변이 있는 사이트
  bcftools view --threads 3 -S control.txt $V | bcftools view --threads 3 -c1 -Oz > col_var.vcf.gz
  # control에서 결측(missing)인 사이트
  bcftools view --threads 3 -S control.txt $V | bcftools view --threads 3 -g miss -Oz > col_miss.vcf.gz
  tabix -f group_var.vcf.gz; tabix -f col_var.vcf.gz; tabix -f col_miss.vcf.gz
  bcftools isec --threads 3 -n~100 -w 1 -Oz -p intersect \
      group_var.vcf.gz col_var.vcf.gz col_miss.vcf.gz
  mv intersect/0000.vcf.gz <NAME>_spec.vcf.gz
done
```
| **OUT** | `SNVs_only_spec.vcf.gz` **10,430** / `non_SNVs_spec.vcf.gz` **2,047** / `SVs_spec.vcf.gz` **202** |
|---|---|

**옵션 의미 (핵심):**
| 옵션 | 의미 |
|---|---|
| `-S our.txt` | 해당 **샘플만 골라냄**(subset) |
| `-c1` | `--min-ac 1` — **ALT 대립이 최소 1개** 있는 사이트만 = "변이 있는 곳" |
| `-g miss` | genotype이 **결측(./.)** 인 사이트만 |
| `isec -n~100` | **교집합 패턴 지정** — `~`는 비트마스크: `1`=있음, `0`=없음.<br>`100` = **첫 파일(our)엔 있고 2·3번(control 변이·결측)엔 없음** |
| `-w 1` | 출력을 **1번 파일 기준**으로 씀(write) |
| `-p intersect` | 결과를 이 **폴더**에 씀 → `0000.vcf.gz`가 우리가 원하는 것 |
| `tabix -f` | isec은 **인덱스 필수** → 강제(`-f`) 생성 |

**해석:** "our에는 변이가 있는데 control(CHM13)에는 변이도 없고 결측도 아닌(=확실히 참조와
같은) 사이트" → 이 집단에 특징적인 변이.

### (3) 개인 특이 변이
```bash
for SAMPLE in $(bcftools query -l $V); do
  bcftools view -s $SAMPLE  $V | bcftools view -c1 -o sample_var.vcf.gz -Oz   # 이 샘플에 있는
  bcftools view -s ^$SAMPLE $V | bcftools view -c1 -o other_var.vcf.gz  -Oz   # 나머지에 있는
  tabix -f sample_var.vcf.gz; tabix -f other_var.vcf.gz
  bcftools isec --threads 3 -n~10 -w 1 -Oz -p intersect sample_var.vcf.gz other_var.vcf.gz
  mv intersect/0000.vcf.gz ${SAMPLE}_spec.vcf.gz
done
```
| **OUT** | `03_individual_spec_var/<타입>_spec/<샘플>_spec.vcf.gz` (3타입×4샘플 = **12개**) |
|---|---|
| **결과(SNV)** | sample01=1,558 / 02=923 / 03=1,162 / 04=834 |

- `query -l` : VCF의 **샘플명 목록** 출력
- `-s ^$SAMPLE` : `^`는 **제외** — 이 샘플만 빼고 나머지 전부
- `isec -n~10` : 1번(이 샘플)엔 있고 2번(나머지)엔 없음 = **개인 특이**

# PHASE 2 — 실습 2 (vg giraffe SV genotyping) · Linux x86_64 전용

**작업 폴더:** `$WORK/04_vg_sv_genotyping`

## 2-① KMC + 개인 맞춤 그래프 (**vg 1.67.0** 사용)
```bash
export PATH=$ROOT/tools/vg167_kmc324/bin:$PATH   # ★vg 1.67.0 + kmc
printf "%s\n%s\n" "$R1" "$R2" > 01_sample/${SAMPLE}.fastq_list.txt
kmc -k29 -m64 -okff -t3 @01_sample/${SAMPLE}.fastq_list.txt 01_sample/${SAMPLE}.srWGS 01_sample
vg haplotypes -v 2 -t 3 --include-reference --diploid-sampling \
   -i $DATA/OUR.hapl -k 01_sample/${SAMPLE}.srWGS.kff \
   -g 01_sample/${SAMPLE}_sampled.gbz $DATA/OUR.gbz
vg snarls -t 3 01_sample/${SAMPLE}_sampled.gbz > 01_sample/${SAMPLE}_sampled.snarls
```
| | |
|---|---|
| **IN** | `$SRWGS/{SAMPLE}_1.fq.gz`, `_2.fq.gz` / `$DATA/OUR.gbz` / `$DATA/OUR.hapl` |
| **OUT** | `01_sample/{SAMPLE}.srWGS.kff` (k-mer 카운트)<br>`01_sample/{SAMPLE}_sampled.gbz` (**개인 맞춤 그래프**)<br>`01_sample/{SAMPLE}_sampled.snarls` (거품 목록) |

**KMC 옵션:**
| 옵션 | 의미 |
|---|---|
| `-k29` | **k-mer 길이 29** (vg haplotypes가 요구하는 값) |
| `-m64` | 메모리 상한 **64GB** |
| `-okff` | 출력 형식 **KFF** (vg가 읽는 k-mer 파일 포맷) |
| `-t3` | 3스레드 |
| `@파일` | **파일 목록**을 파일로 전달 (`@`가 리스트 표시) |
| 마지막 인자 | 출력 prefix, 그리고 **임시 작업 폴더** |

**vg haplotypes 옵션:**
| 옵션 | 의미 |
|---|---|
| `-v 2` | verbosity 2 (진행 로그) |
| `--include-reference` | 결과 그래프에 **참조 경로 포함** (뒤의 surject·call에 필요) |
| `--diploid-sampling` | **이배체 샘플링** — 부계·모계 2벌을 뽑음 |
| `-i OUR.hapl` | 입력 **하플로타입 패널** |
| `-k *.kff` | 이 샘플의 **k-mer 카운트** → 어떤 하플로타입이 이 사람에 맞는지 판단 |
| `-g out.gbz` | 출력 **개인 맞춤 GBZ** |

> **왜 vg 1.67.0인가:** 이 `.hapl` 파일이 구버전 포맷이라 1.67.0에서만 호환됩니다.
> 이후 단계는 1.74.1을 씁니다 (강사 스크립트가 의도한 버전 분리).

## 2-② vg giraffe 매핑 (**vg 1.74.1**)
```bash
export PATH=$ROOT/tools/vg174_kmc324/bin:$PATH   # ★vg 1.74.1
vg giraffe -p -t 3 -Z 01_sample/${SAMPLE}_sampled.gbz -f "$R1" -f "$R2" \
   > 02_SR_mapping/${SAMPLE}.chr2_1-5Mb.gam 2> 02_SR_mapping/${SAMPLE}.chr2_1-5Mb.gam.log
vg stats --threads 3 -a 02_SR_mapping/${SAMPLE}.chr2_1-5Mb.gam \
   > 02_SR_mapping/${SAMPLE}.chr2_1-5Mb.gam.stats.txt
```
| | |
|---|---|
| **IN** | `01_sample/{SAMPLE}_sampled.gbz`, FASTQ 2개 |
| **OUT** | `02_SR_mapping/{SAMPLE}.chr2_1-5Mb.gam` (**그래프 정렬**)<br>`.gam.stats.txt` (통계), `.gam.log` (로그) |
| **결과** | HG00438: total 1,230,694 / **aligned 805,888** · HG02257: aligned 814,909 |

| 옵션 | 의미 |
|---|---|
| `-p` | **진행률(progress)** 표시 |
| `-Z` | 입력 그래프가 **GBZ 형식**임을 지정 |
| `-f R1 -f R2` | FASTQ — **두 번 쓰면 paired-end**로 인식 |
| `> .gam` | GAM은 **stdout으로 나오므로 리다이렉트 필수** |
| `vg stats -a` | GAM **정렬 통계** (aligned/perfect/mapq 등) |

## 2-③ vg pack + vg call (**vg 1.74.1**)
```bash
vg pack -t 3 -x 01_sample/${SAMPLE}_sampled.gbz \
   --gam 02_SR_mapping/${SAMPLE}.chr2_1-5Mb.gam \
   -o 03_SV_call/${SAMPLE}.pack --min-mapq 5
vg call -t 3 --ref-sample GRCh38 01_sample/${SAMPLE}_sampled.gbz \
   --genotype-snarls --all-snarls --snarls 01_sample/${SAMPLE}_sampled.snarls \

bcftools index 03_SV_call/${SAMPLE}.vg.call.vcf.gz
# 두 샘플 병합
bcftools merge -m all 03_SV_call/*.vg.call.vcf.gz -Oz \

```

|---|---|

## 3-① surject: GAM → GRCh38 BAM (**vg 1.74.1**)
```bash
export PATH=$ROOT/tools/vg174_kmc324/bin:$PATH
vg paths -x $DATA/OUR.full.gbz -S GRCh38 -L > surject/GRCh38.${SAMPLE}.paths.txt
PATH_CONTIG=$(head -n1 surject/GRCh38.${SAMPLE}.paths.txt)
vg surject -t 3 -x $WORK/04_vg_sv_genotyping/01_sample/${SAMPLE}_sampled.gbz \
   -F surject/GRCh38.${SAMPLE}.paths.txt -b -i \
   -N ${SAMPLE} -R "ID:1\tLB:lib1\tSM:${SAMPLE}\tPL:illumina\tPU:unit1" \
   $WORK/04_vg_sv_genotyping/02_SR_mapping/${SAMPLE}.chr2_1-5Mb.gam \
   | samtools sort -@ 3 -O BAM -o surject/${SAMPLE}.raw.bam
# contig 이름을 chr2 로 교체 (DeepVariant가 FASTA와 이름이 맞아야 함)
samtools view -H surject/${SAMPLE}.raw.bam \
  | awk -v old="$PATH_CONTIG" -v new="chr2" 'BEGIN{OFS="\t"} /^@SQ/{for(i=1;i<=NF;i++) if($i=="SN:"old)$i="SN:"new}{print}' \
  > surject/${SAMPLE}.reheader.sam
samtools reheader surject/${SAMPLE}.reheader.sam surject/${SAMPLE}.raw.bam \
  > surject/${SAMPLE}.grch38.chr2_1-5Mb.bam
samtools index surject/${SAMPLE}.grch38.chr2_1-5Mb.bam
samtools flagstat --output-fmt tsv surject/${SAMPLE}.grch38.chr2_1-5Mb.bam \
  > surject/${SAMPLE}.flagstat.tsv
```
| | |
|---|---|
| **IN** | `$DATA/OUR.full.gbz` (참조 경로용), `_sampled.gbz`, `.gam` |
| **OUT** | `surject/GRCh38.{SAMPLE}.paths.txt` (참조 경로명)<br>**`surject/{SAMPLE}.grch38.chr2_1-5Mb.bam`** (+`.bai`)<br>`surject/{SAMPLE}.flagstat.tsv` |
| **결과** | HG00438: **mapped 804,384 (65.36%)** |

| 옵션 | 의미 |
|---|---|
| `paths -x ... -S GRCh38 -L` | GBZ에서 **GRCh38 샘플의 경로 이름만 나열**(`-L`=list) |
| `surject -x` | **매핑에 쓴 것과 같은 그래프** (좌표 일관성 필수) |
| `surject -F paths.txt` | 이 **경로들로 투영**(project) |
| `surject -b` | 출력 **BAM** |
| `surject -i` | **paired-end** 로 처리(interleaved) |
| `surject -N` | 샘플 이름 |
| `surject -R "ID:..."` | BAM **@RG 리드그룹** 지정 — DeepVariant가 요구 |
| `samtools sort -O BAM` | 좌표 정렬 (index·DeepVariant 전제조건) |
| `reheader` | `@SQ`의 contig명을 `GRCh38#0#chr2` → **`chr2`** 로 바꿔 FASTA와 일치시킴 |
| `flagstat --output-fmt tsv` | 매핑률 요약(TSV) — **정답 대조용** |

> `OUR.gbz`(매핑용)와 `OUR.full.gbz`(참조 경로용)를 **다르게 쓰는 이유**: full 쪽이
> 조각나지 않은 온전한 GRCh38 경로를 갖고 있어 투영 기준으로 적합합니다.

## 3-② DeepVariant 3단계 직접 호출 + GLnexus
```bash
# 입력 준비 (컨테이너에 bind할 폴더로 복사)
mkdir -p input output joint tmp_${SAMPLE}
cp $DATA/GRCh38.chr2_1-5Mb.fa $DATA/GRCh38.chr2_1-5Mb.fa.fai $DATA/OUR.gbz input/
cp surject/${SAMPLE}.grch38.chr2_1-5Mb.bam{,.bai} input/

apptainer exec \
  --bind "$(pwd)/input:/input" --bind "$(pwd)/output:/output" --bind "$(pwd)/tmp_${SAMPLE}:/work" \
  $ROOT/tools/deepvariant_pangenome_aware_1.8.0.sif bash -c "
    # ① make_examples — pileup image 생성 (3 shard 병렬)
    seq 0 2 | parallel -q --halt 2 --line-buffer \
      /opt/deepvariant/bin/make_examples_pangenome_aware_dv \
        --mode calling \
        --ref /input/GRCh38.chr2_1-5Mb.fa \
        --reads /input/${SAMPLE}.grch38.chr2_1-5Mb.bam \
        --pangenome /input/OUR.gbz \
        --examples /work/make_examples_pangenome_aware_dv.tfrecord@3.gz \
        --checkpoint /opt/models/pangenome_aware_deepvariant/wgs \
        --gvcf /work/gvcf.tfrecord@3.gz \
        --keep_legacy_allele_counter_behavior \
        --keep_only_window_spanning_haplotypes \
        --keep_supplementary_alignments \
        --min_mapping_quality 0 --normalize_reads \
        --sample_name_pangenome hprc_v1.1 \
        --sort_by_haplotypes --trim_reads_for_pileup \
        --task {}
    # ② call_variants — CNN 추론
    /opt/deepvariant/bin/call_variants \
      --outfile /work/call_variants_output.tfrecord.gz \
      --examples /work/make_examples_pangenome_aware_dv.tfrecord@3.gz \
      --checkpoint /opt/models/pangenome_aware_deepvariant/wgs
    # ③ postprocess_variants — VCF/gVCF 출력
    /opt/deepvariant/bin/postprocess_variants \
      --ref /input/GRCh38.chr2_1-5Mb.fa \
      --infile /work/call_variants_output.tfrecord.gz \
      --outfile /output/${SAMPLE}.pgdv.vcf.gz \
      --gvcf_outfile /output/${SAMPLE}.pgdv.g.vcf.gz \
      --nonvariant_site_tfrecord_path /work/gvcf.tfrecord@3.gz
  "
# 다중샘플 통합
glnexus_cli --config DeepVariantWGS output/*.pgdv.g.vcf.gz \
  | bcftools view -Oz -o joint/OUR.pgdv.GLnexus.chr2_1-5Mb.vcf.gz
```
| | |
|---|---|
| **IN** | `surject/{SAMPLE}.grch38.chr2_1-5Mb.bam`, `$DATA/GRCh38.chr2_1-5Mb.fa`, `$DATA/OUR.gbz` |
| **OUT** | `output/{SAMPLE}.pgdv.vcf.gz` (HG00438 21,838 / HG02257 21,733)<br>`output/{SAMPLE}.pgdv.g.vcf.gz` (gVCF)<br>**`joint/OUR.pgdv.GLnexus.chr2_1-5Mb.vcf.gz`** (통합 **6,703**개) |

**DeepVariant 3단계 = 논문(Poplin 2018) Figure 1과 1:1 대응:**
| 단계 | 하는 일 |
|---|---|
| `make_examples_pangenome_aware_dv` | 변이 후보마다 **pileup image**(read + **판지놈 하플로타입**) 생성 |
| `call_variants` | **CNN**이 각 이미지의 유전형 확률 예측 |
| `postprocess_variants` | 확률을 모아 **VCF/gVCF** 출력 |

**주요 옵션:**
| 옵션 | 의미 |
|---|---|
| `--mode calling` | 추론 모드 (학습이 아님) |
| `--pangenome /input/OUR.gbz` | ★**판지놈 채널** — 이게 pangenome-aware의 핵심 |
| `--examples ...@3.gz` | `@3` = **3개 shard로 분할** 출력 (병렬) |
| `--checkpoint /opt/models/pangenome_aware_deepvariant/wgs` | 학습된 **모델 가중치**(WGS용) |
| `--gvcf` | gVCF용 중간 기록 (비변이 사이트 포함) |
| `--sample_name_pangenome hprc_v1.1` | 판지놈 쪽 샘플 이름표 |
| `--sort_by_haplotypes` | pileup에서 read를 **하플로타입별로 정렬** |
| `--min_mapping_quality 0` | MAPQ 필터 없음 (그래프 매핑 read는 MAPQ가 낮게 나오는 경향) |
| `--trim_reads_for_pileup` | 이미지 창 밖 read 잘라냄 |
| `--normalize_reads` | read 정규화 |
| `--task {}` | parallel이 넘기는 **shard 번호**(0,1,2) |
| `parallel --halt 2` | 하나 실패하면 **즉시 전체 중단** |
| `glnexus_cli --config DeepVariantWGS` | DeepVariant WGS gVCF용 **공동 genotyping 프리셋** |
| `apptainer exec --bind A:B` | 호스트 폴더 A를 컨테이너 B에 **마운트** |

> ⚠️ **공유메모리 이슈:** 원래 래퍼 `run_pangenome_aware_deepvariant`는 판지놈을
> `/dev/shm/GBZ_SHARED_MEMORY`(고정 이름)에 올려 shard가 공유합니다. 공용 서버에서 다른
> 사용자와 **이름 충돌** 시 `RuntimeError: File exists`로 죽습니다. 위처럼 **3단계를 직접
> 호출하면 공유메모리를 쓰지 않아** 이 문제가 사라집니다 (toy 데이터라 성능 손해 없음).

> **환경 주의:** `apptainer`가 없고 `singularity`만 있는 서버가 많습니다(예: WONLAB-hpc는
> singularity 3.8.7). 둘은 CLI가 호환되므로 마스터 스크립트는 **있는 것을 자동으로 감지**해
> 사용하며 시작 시 `[INFO] CONTAINER = ...` 로 알려줍니다. 자동 감지가 안 되면
> `export KOGO_CONTAINER=/usr/local/bin/singularity` 로 지정하세요.
